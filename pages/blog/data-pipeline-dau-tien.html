Designing Your First Data Pipeline

A clean data pipeline can start with a daily CSV file and end at a verifiable, traceable, and re-runnable reporting table.

Table of Contents

  1. Mapping the Data Flow
  2. Validation Before Ingestion
  3. Designing for Re-runs

Mapping the Data Flow

Suppose an e-commerce platform generates a daily CSV file containing paid orders each morning. The business report requires daily order counts and revenue. The initial flow requires three distinct steps:

  1. Extract — Store the raw source file, recording file name, checksum, and arrival timestamp.
  2. Transform — Parse and normalize timestamps, currency amounts, and order identifiers into an intermediate staging table.
  3. Load — Aggregate validated records into the daily reporting table.

Validation Before Ingestion

Verify required columns, detect duplicate order IDs, and reconcile record counts between the input file and the staging table. For invalid rows, log error reasons into a dead-letter sink to facilitate source auditing and manual correction.

After standardizing data types, the query below aggregates orders for a given reporting date:

SELECT
  order_date,
  COUNT(*) AS total_orders,
  SUM(amount) AS total_revenue
FROM staging_orders
WHERE order_date = :report_date
GROUP BY order_date;

Designing for Re-runs

Use the reporting date as an execution parameter. After validation succeeds, replace that specific date's partition within a single transaction. Re-running the pipeline with identical input produces the exact same results without duplicating metrics.

Log execution statuses alongside received, valid, and rejected record counts. When numbers diverge, you can trace discrepancies directly back to the original source file.
